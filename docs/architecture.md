# Карта архітектури Colonies

**JSON → визначення сутностей → стан гри → дія початку кола → селектори → інтерфейс**

## Де змінювати гру

| Завдання | Місце |
| --- | --- |
| Змінити стартові монети, дослідників, транспорт, пул магазину | `src/game/game-config.json` |
| Додати карту, іконку, місткість або характеристики транспорту | `src/game/cards.json` |
| Змінити грані прогнозу | `src/game/dice-config.json` |
| Змінити розрахунок доходу або переповнення | `src/game/rules.ts` |
| Змінити дозволені дії чи джерело випадковості | `src/game/Colonies.ts` |
| Змінити 3D-розташування або камеру | `src/components/table3d/TableScene.tsx` |
| Змінити перегляд карт, баланс чи картку фаз | `src/components/` |
| Додати перевірку та її виконувану візуалізацію | `src/game/live-scenarios.ts`, `src/game/*.test.ts` |

## Контракти між шарами

1. `cards.ts` і `config.ts` перевіряють JSON при завантаженні. Неправильні ресурси, характеристики, слоти й дубльовані ID не проходять. `wallet` зберігає монети, `slots` — енергію або зброю; нуль слотів підсилювачів коректний.
2. Визначення карт — спільний незмінний довідник. Екземпляри мають окремі ID, слоти та оснащення. `buildings.ts` і `aircraft.ts` створюють їх; `state.ts` описує стан гри. Кожен дослідник також має власний ID.
3. `Colonies.setup` отримує випадковий порядок магазину від boardgame.io й передає його в чисту `createInitialState`. До першого кидка є магазин, але немає доходу.
4. `rollDice` перевіряє лідера до звернення до генератора випадковості. boardgame.io виконує `D6` і `Shuffle`; `resolveRound` збільшує `G.round`, оновлює магазин і застосовує виробництво всім гравцям одним переходом стану. `G.round` — наше коло, не внутрішній `ctx.turn` рушія.
5. `applyProduction` повертає новий стан гравця, не змінюючи вхідний. Монети додаються до гаманця; фішки енергії — лише у вільні слоти відповідної установки. Надлишок не зберігається, уже наявні фішки не видаляються. Тригер зброї `null` означає відсутність виробництва.
6. `getPlayerBalance` читає гаманець і сумує фішки. Інших лічильників енергії/зброї чи загального запасу немає. HUD і текстури 3D використовують цей селектор; інтерфейс не нараховує дохід.
7. React показує стан і викликає дії рушія. Камери, дебаг-параметри й відкритий перегляд карти — локальний стан інтерфейсу, не правила гри.

## Як перевіряємо

`npm run check` = Vitest 4.0.18 → TypeScript → production-збірка Vite. Інтеграційні тести використовують справжній клієнт boardgame.io; однаковий seed і дії повинні давати однаковий стан, без статистичних припущень.

Сторінка `#/tests` запускає функції з `live-scenarios.ts`, які перевіряються також у Vitest, і показує фактичний результат поруч з очікуваним. Виробничі сценарії використовують явні тестові колонії з `scenario-fixtures.ts`, не змінюючи поточну партію. Старі приклади ініціативи й подій монстрів — лише демонстрації, без виконання механіки.

## Поточні межі

Є стартовий стан, прогноз, магазин і дохід. Немає призначення груп, покупок, оснащення, бою, дебафів, ботів, передачі коронки й сейвів. Ядро підтримує 2–4 гравців; сцена має три демонстраційні місця. Каталог підсилювачів/монстрів і чотири карти розвитку лишаються заготовками.
