# The Colonies

Вебпрототип настільної гри для візуальних плейтестів людини проти ботів.

## Джерело задуму

[Поточний лор, механіки та відкриті питання](docs/game-design.md).

Документ спирається на нове диктування автора від 11 жовтня 2026 року й наступні уточнення: ініціатива, кубики, монстри, стартова колонія, дохід і базовий транспорт. Старі нотатки Obsidian не є канонічними правилами цього проєкту.

## Узгоджений напрям розробки

- React + boardgame.io, із відокремленим ядром правил.
- Візуальна гра проти локальних евристичних ботів-архетипів: економіст, експедитор, дослідник, агресор.
- Канонічні параметри, контент і варіанти правил — у YAML/JSON; читабельне пояснення — у Markdown.
- Налаштування балансу між партіями; збереження конфігурації конкретного плейтесту.
- Notion — для співпраці, дизайн-рішень і висновків із тестів.
- Dextrous — для друкованих прототипів карт із даних проєкту.

Числа з прикладів не стають автоматично параметрами гри. Затверджені стартові параметри, каталог і грані кубиків уже винесені в JSON; нові варіанти правил додаються після узгодження.

## Вебпрототип

React + TypeScript + Vite + boardgame.io. Кожен гравець починає з **5 помаранчевими дослідниками, 3 монетами, «Осердям» без слотів і одним базовим конвертопланом (+2 ініціативи / вантажність 4 / підсилювачі 0)**. Колонія не містить інших установок. П'ять порожніх карт у руці — налаштування макета, не затверджене правило.

Кожен кидок лідера починає нове коло: чотири кубики → заміна чотирьох карт магазину → дохід усіх гравців. «Осердя» додає одну монету незалежно від прогнозу. Сонце й вітер дають по одній енергії відповідним установкам за кожний символ, тільки у вільні слоти; надлишок втрачається. Збройні установки поки не виробляють. Початковий магазин готовий до першого кидка, але дохід ще не нарахований. Магазин вибирається без повторень із семи нових установок, без «Осердя»; між колами назви можуть повторюватися, колоди/скиду немає.

Монети — числовий гаманець без ігрового ліміту. Енергія й зброя — лише фішки на установках; баланс підсумовує їхні слоти, без другого незалежного лічильника. Сонячна й вітрова енергія — один ресурс.

```sh
npm ci
npm run dev
```

Потрібен Node 20.19+ (перевірено на 20.19.5). Vitest зафіксовано на 4.0.18 у `package.json` і lock-файлі, без оновлення решти стеку.

```sh
npm run test        # усі автоматичні перевірки, одноразово
npm run test:watch  # перевірки при змінах
npm run build      # TypeScript + production-збірка у dist/
npm run check      # автотести, потім збірка
```

- `src/game/Colonies.ts` — інтеграція boardgame.io, авторизація кидка й випадковість.
- `src/game/game-config.json` — стартові параметри, пул/розмір магазину та картка фаз кола; `config.ts` перевіряє значення й посилання.
- `src/game/cards.json` — визначення карт; `cards.ts` перевіряє каталог, `buildings.ts` і `aircraft.ts` створюють їхні екземпляри.
- `src/game/state.ts` — форма стану; `rules.ts` — чисті функції старту, виробництва, магазину та селектор балансу.
- `src/game/scene.json` — назви секцій і кількість карт макета.
- `src/game/dice-config.json` — шість граней кожного із чотирьох кубиків прогнозу; дублікати задають імовірності явищ.
- `src/components/GameTable.tsx` — компонування ігрового столу.
- `src/styles.css` — вигляд меню, поля та карт.

`ResourceSlot` показує порожнє місце або фішку зброї/енергії. «Осердя» використовує `storage: { "mode": "wallet", "resource": "coin" }` без `slotCount`; установки накопичення — `storage: { "mode": "slots", "resource": "energy", "slotCount": 2 }`. Загального масиву вільних ресурсів немає.

Секція 3 залишена без конкретної механіки; розвиток містить чотири заготовки. Розподіл груп, покупки/крафт, оснащення транспорту, бій, дебафи монстрів, боти та збереження партій ще не реалізовані. Лідер не передається автоматично. Міграція сейвів не потрібна — їх ще немає.

## 3D-стіл

Three.js + React Three Fiber + Drei показують стіл із трьома демонстраційними місцями. У центрі — планшет, навколо — колонії, кубики-дослідники, баланс, транспорт праворуч і руки карт. Чужі руки показуються сорочками. Магазин показує справжні установки; натискання на них або транспорт відкриває перегляд, не покупку. Монети показуються лише числом, енергія й зброя фізично лежать лише в слотах установок. Зброя має червоний значок.

За замовчуванням камера показує наближений перспективний вид із місця гравця: власна колонія попереду, центральний планшет далі. Кнопка «Зверху» вмикає ортографічний огляд усього столу без викривлень. Обертання вимкнене в обох режимах. Перетягування пересуває поле, колесо змінює масштаб. «Початковий ракурс» повертає початкове положення та масштаб поточного режиму. Натискання на публічну установку або власну карту відкриває великий перегляд; закриття — кнопкою, Escape або натисканням поза вікном.

`src/components/table3d/` містить 3D-сцену й локально згенеровані текстури. Правила залишаються у `src/game/`, незалежно від візуалізації. Усі три гравці мають справжній стартовий стан і отримують дохід; двоє інших не мають AI чи самостійних дій. Ядро протестоване для 2–4 гравців; компонування столу на чотирьох — окремий етап. Обидві камери й дебаг-панель кута/зуму збережені. Картка фаз відділяє два реалізовані кроки від чотирьох запланованих.

## Майстерня: правила, карти й тест-кейси

У головному меню є посилання на три сторінки:

- `#/rules` — документація з `docs/game-design.md`, розділена на тематичні групи. Є пошук по тексту розділів, таблиці, посилання на конкретний розділ (`#/rules?section=5`) і завантаження Markdown. Рендеринг: `react-markdown` + `remark-gfm`; HTML із Markdown не виконується.
- `#/tests` — п'ять **виконуваних** сценаріїв старту, балансу, виробництва, переповнення й магазину та шість старих **демонстрацій** ініціативи/монстрів. Нові сценарії запускають спільні з автотестами функції й показують фактичний та очікуваний результат кожної перевірки. Це не запуск усього Vitest у браузері; старі демонстрації не видаються за перевірені правила. Є пошук, фільтр механік і три кроки огляду.
- `#/cards` — категорії «Установки», «Конвертоплани», «Підсилювачі», «Монстри та катастрофи». Усе читається із `src/game/cards.json`. Установки й транспорт використовують ті самі компоненти, що й перегляд у грі. Підсилювачі та монстри — явно позначені заготовки. Є фільтри, характеристики й посилання на правила.

Щоб додати карту, додай об’єкт до `cards` у `src/game/cards.json` (схема 2) із унікальним `id` та наявним `categoryId`. `status: "placeholder"` означає заготовку, `"prototype"` — визначену карту прототипу. Установці потрібні `production` (ресурс, кількість, тригер `round`/`sun`/`wind`/`null`) та `storage`. Транспорт має `stats: { "initiative": 2, "cargoCapacity": 4, "boosterSlots": 0 }`; нуль слотів дозволений. Підсилювачам і монстрам потрібні описи `effects`; `text: null` показує «Ще не визначено». Опис ефекту не є виконуваним правилом. Завантажувач перевіряє типи, ресурси, характеристики, слоти, унікальні ID й відповідність категорій. Для потрапляння установки в магазин додай її ID до пулу в `game-config.json`.

Компоненти майстерні — `src/components/reference/`, приклади сценаріїв — `src/game/test-scenarios.ts`. Сторінки завантажуються ліниво. Hash-навігація підтримує прямі посилання без окремого серверного маршрутизатора.

## Архітектура й перевірки

**JSON → визначення сутностей → стан гри → дія початку кола → селектори → інтерфейс.** [Коротка карта архітектури й точки змін](docs/architecture.md).

`rules.test.ts` перевіряє старт для 2/3/4 гравців, ID, гаманець і баланс, виробництво/переповнення, магазин, авторизацію кидка й повторюваність boardgame.io за однаковим seed. `cards.test.ts` перевіряє JSON, включно з неправильними ресурсами, характеристиками та дубльованими ID. Немає статистичних тестів, що можуть випадково падати.

`live-scenarios.ts` містить виконувані сценарії для браузера й автотестів. `scenario-fixtures.ts` створює спеціальні колонії з установками тільки для перевірок; звичайним гравцям їх не додає. Перевірка інтерфейсу в Chrome доповнює, а не замінює автотести.
