# The Colonies

Вебпрототип настільної гри для візуальних плейтестів людини проти ботів.

## Джерело задуму

[Поточний лор, механіки та відкриті питання](docs/game-design.md).

Документ спирається на нове диктування автора від 11 жовтня 2026 року та уточнення від 12 жовтня: ініціатива груп, кубики прогнозу, монстри й екологічні катастрофи. Старі нотатки Obsidian не є канонічними правилами цього проєкту.

## Узгоджений напрям розробки

- React + boardgame.io, із відокремленим ядром правил.
- Візуальна гра проти локальних евристичних ботів-архетипів: економіст, експедитор, дослідник, агресор.
- Канонічні параметри, контент і варіанти правил — у YAML/JSON; читабельне пояснення — у Markdown.
- Налаштування балансу між партіями; збереження конфігурації конкретного плейтесту.
- Notion — для співпраці, дизайн-рішень і висновків із тестів.
- Dextrous — для друкованих прототипів карт із даних проєкту.

Спочатку формалізуємо нові правила. Числа з прикладів не стають автоматично параметрами гри. Конфіги ігрових правил ще не реалізовані.

## Вебпрототип

React + TypeScript + Vite + boardgame.io. Поточний прототип містить меню, кнопку «Старт» і макет ігрового столу з чотирма секціями, установкою «Осердя» та рукою порожніх карт. П'ять карт у руці — налаштування макета, а не затверджене правило.

```sh
npm install
npm run dev
```

`npm run build` перевіряє TypeScript і збирає застосунок у `dist/`.

- `src/game/Colonies.ts` — початковий стан boardgame.io.
- `src/game/scene.json` — назви секцій і кількість карт макета.
- `src/game/dice-config.json` — шість граней кожного із чотирьох кубиків прогнозу; дублікати задають імовірності, або збільшують кількість одиниць прибутку.
- `src/components/GameTable.tsx` — компонування ігрового столу.
- `src/styles.css` — вигляд меню, поля та карт.

`src/game/cards.json` задає категорії й карти: назви, іконки, статуси, описові ефекти, виробництво установок та 1–3 слоти. `cards.ts` перевіряє дані; `buildings.ts` формує довідник ігрових установок із цього JSON. `ResourceSlot` показує порожнє місце або фішечку, `ResourceChip` — фішечку монети, зброї чи енергії. Купол виробляє `1 🪙` за описом і стартує з порожнім слотом.

Секція 3 залишена без конкретної механіки. Правила, боти, розіграш карт і збереження партій ще не реалізовані.

## 3D-стіл

Three.js + React Three Fiber + Drei показують стіл із трьома демонстраційними місцями гравців. У центрі — планшет, навколо — колонії з «Осердям» та руки карт. Чужі руки показуються сорочками; власні карти доступні для перегляду. Фішечки на окремому лотку — зразки, а не стартові ресурси гравців.

За замовчуванням камера показує наближений перспективний вид із місця гравця: власна колонія попереду, центральний планшет далі. Кнопка «Зверху» вмикає ортографічний огляд усього столу без викривлень. Обертання вимкнене в обох режимах. Перетягування пересуває поле, колесо змінює масштаб. «Початковий ракурс» повертає початкове положення та масштаб поточного режиму. Натискання на публічну установку або власну карту відкриває великий перегляд; закриття — кнопкою, Escape або натисканням поза вікном.

`src/components/table3d/` містить 3D-сцену та локально згенеровані текстури. Правила залишаються у `src/game/`, незалежно від візуалізації. Два інші місця зараз є макетами гравців, без AI чи виконання ходів.

## Майстерня: правила, карти й тест-кейси

У головному меню є посилання на три сторінки:

- `#/rules` — документація з `docs/game-design.md`, розділена на тематичні групи. Є пошук по тексту розділів, таблиці, посилання на конкретний розділ (`#/rules?section=5`) і завантаження Markdown. Рендеринг: `react-markdown` + `remark-gfm`; HTML із Markdown не виконується.
- `#/tests` — інтерактивний макет візуалізації шести сценаріїв. Є пошук, фільтр механік і три кроки: початковий стан, дія, очікуваний результат. Це демонстраційні дані, не запуск рушія й не результати автотестів.
- `#/cards` — каталог за категоріями «Установки», «Підсилювачі», «Монстри та катастрофи». Усі категорії, карти та їхні характеристики читаються із `src/game/cards.json`. Установки використовують той самий компонент карти, що й гра. Інші категорії містять явно позначені заготовки, не ігрові сутності. Є фільтр категорій, параметри установки й посилання на відповідні правила.

Щоб додати карту, додай об’єкт до `cards` у `src/game/cards.json` із унікальним `id` та наявним `categoryId`. `status: "placeholder"` означає заготовку, `"prototype"` — визначену карту прототипу. Для установок потрібні `production` та `storage`; для підсилювачів і монстрів — масив описів `effects`. `text: null` показує «Ще не визначено». Опис ефекту не є виконуваним правилом. Завантажувач перевіряє версію, типи, ресурси, слоти 1–3, унікальні ідентифікатори та відповідність категорій.

Компоненти майстерні — `src/components/reference/`, приклади сценаріїв — `src/game/test-scenarios.ts`. Сторінки завантажуються ліниво. Hash-навігація підтримує прямі посилання без окремого серверного маршрутизатора.
